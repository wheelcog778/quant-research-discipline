# 否决器 · 因子与策略的证伪流程

**v1.8.1（2026-11-04）**：补 v1.8.0 的口径漏洞——`yearly` 原先没接 `untradable_by_code`，同一份数据同一个持有期，`ic` 与 `yearly` 会给出两个 IC（实测 +0.0097 vs +0.0111，t_HAC +0.69 vs +0.81）。现在 `ic`/`yearly`/`sim` 三处同口径，`yearly` 表头打印「不可成交剔除 N 条」；同时把「全部入场不可成交」时的报错从「检查日期/代码」改成说清原因（`ic` 与 `sim` 各一条）。自检 16 增加「`yearly` 同口径」断言。

**v1.8.0（2026-11-03）**：补齐三大实战短板——①**A 股可交易性硬过滤**：`ic`/`yearly`/`sim` 自动拦截 T+1 入场日停牌（`volume==0`）与一字涨跌停（`high==low`），`sim` 止损遇一字跌停或停牌自动顺延至首个开板日按开盘价离场，消除「涨停买进、跌停按止损价逃顶」的回测假象；②**打通 CSV 与 SQLite 双通道**：`db_lab.py` 补齐独立 CLI `main()` 并修复 `walkforward(trials=...)` 门槛形参空转，`vkit.py` 新增 `db` 子命令统一调度；③**多重检验自动计次账本**：数据目录自动维护 `.verdict_trials.json` 记录不同参数组合尝试次数，手填 `--trials` 偏低时自动按累计次数抬高 Bonferroni 门槛并告警；自检扩至 **18 项**。

**v1.7.0（2026-11-03）**：统一全包统计与工程门禁——①修掉 `factor_lab.rolling_ic` 残留的 `pstdev or 1e-9` 零方差假 t 兜底（常数分段改返 `None`/不可估）；②`spread_summary` 与 `pool_lab.py` 的 `alpha_t` 全部统一接入 `factor_lab.hac_t_overlap`（消除 Bartlett 单核与朴素 t 的三处口径分裂）；③`db_lab.py` 与 `pool_lab.py` 补齐正整数持有期/top-N/非负成本入口校验与 SQL 参数化防注入，`db_lab` 成本表补齐持有期列；④`references/case-study.md` 章节标题与末节边界对齐七件套检查器（`doctrine_check.py` 实测可引用），全包通过 `version_lint.py` 与 `doc_dup_scan.py`（0 重复）；自检由 13 项扩至 **15 项**。

**v1.6（2026-11-02）**：把同一天里分叉的两版 v1.3 合成一个基线——统计口径用本仓的
（`overlap_t` 把持期重叠的假阳性压到 5.0%；`ic` 与 `sim` 同为 T+1 收盘入场），
入口闸门与文档措辞用另一分支的：`--horizons` 负数/零/重复**在入口拒绝**（合并前 `-5` 会静默
输出一张「−5日」表并标 ✅，用的是回看收益）、`volume<0` 与空日期读数即拒、分档价差零方差
返回"不可估"而不是用 1e-9 兜出一个假 t、除权不再仅凭 −11.5% 阈值自动认定。
自检扩到 **13 项**（v1.8.0 起为 **18 项**），新增「非法持有期被拒」「坏行情被拒」两项。

**v1.5（2026-11-02）**：新增 **关 6.5 · 池子分解与选股消融**——分组 IC 只回答「组内排序有没有效」，
但组合亏钱时得先分清是**选股不行**还是**池子选错**。`scripts/pool_lab.py` 一次扫描出两张表：
① 各池等权收益，用「被剔除池 − 被保留池」给门槛的过路费标价（毛口径）；
② 同一批分数换四种选法（跨类绝对分 / 类内 top-N / 类内百分位 / 百分位阈值）的 alpha 与净值。
判读铁律：**alpha 全正而净值全负 = 分母在跌，问题在池子与换手，不在选股**——此时调选股参数是白费。
实测一例：类内 alpha +0.245%/5 日（t+3.86）为正、5.8 年净值 −70%，被剔除的 82% 毛收益 +84.7%，
被保留的 500 只 −45.3%。同轮按实测证据下调了组合回测与成交假设的完整度分数（见文末表）。

**v1.4**：新增**第 0 关 · 构造效度**——排序之前先验 score 有没有资格被排序。复合打分器里的
门控、封顶（`min(score, X)`）、托底（`max(score, X)`）会让跨组 rank-IC 量到人为构造而非排序能力：
封顶组必然在 IC 里垫底，容易被误写成「避雷信号」；托底组会挤占 top-N，让实际买入集合与
产品说明不是一回事。配套探针 `scripts/probe_score_construct.py`（三张表定性，30 秒），
口径与写法见 `references/score-construct.md`。

**v1.3**：第三轮审查后再修五处，全是会改结论方向的——
① 扣成本写死「低−高」，正向因子必被判 L3；② 组合模拟只按日期聚类，处理不了持有期重叠（假阳性 46%–69%，
名义 5%）；③ `ic` 用 T+1 收盘、`sim` 用 T+1 开盘，两关数字不同口径；④ 因子全同分的截面被记成 IC=0；
⑤ 假阳性验收线 12% 太宽、把"最后一年"直接当样本外；⑥ `ic` 的 t_HAC 仍用 Bartlett 权，
长持有期上低估，现在与配对差共用 `factor_lab.hac_t_overlap`（实测 20 日 IC −2.20 → −1.83，跨过 1.96 线）。
自检扩到十一项（v1.6 起为十三项），每一项都设计成能失败。v1.1–v1.8.0 逐条对照见 `references/CHANGELOG.md`。

## When to Use（何时用）

- 有人说"这个信号/策略有效"，要在投入时间或钱之前验证
- 回测结果"看起来不错"，需要判断是真信号还是拟合
- 策略跑亏了，要判断是参数不对还是东西本身不存在
- 给别人的策略做尽调，出"能不能引用"的结论
- 拿到一份现成的回测报告，只想挑毛病（走"快速通道"，不跑全流程）

**不用于寻找策略。** 它只杀掉假的，不生出真的。

## 核心顺序（不可调换）

> IC/t → 衰减 → 滚动分段 → 分年 → 经济量级（扣成本）→ 集中度 → 组合模拟

判据：**一个策略被判死，不是因为结果难看，是因为所有能救它的解释都被逐一排除。**

## 结论是分级的，不是"死/活"

| 级别 | 条件 | 可以怎么用 |
|---|---|---|
| **L0 数据/口径不足** | 样本 < 几百个横截面日、单一 regime、成本或成交假设缺失 | 只能当假设，不得对外 |
| **L1 未通过** | \|t_HAC\| 低于 Bonferroni 门槛，或分段全在 0 附近 | 停手，别调参 |
| **L2 有稳健反向** | 多期、多段、多源同向为负，且经济量级显著 | 可反向使用（若标的允许做空），否则弃 |
| **L3 有信息但不可实施** | 统计显著，但分档价差 < 双边成本，或容量/换手不可接受 | 只能做负面筛除，不能作为交易信号 |
| **L4 样本内通过** | 七关全过，但未做样本外 | 可继续研究，**不得上钱** |
| **L5 样本外通过** | 样本外同向且量级可接受 | 仍受成交与容量约束，可小仓验证 |

**输出只允许这六种字样。** 写"基本有效""大概率可用"说明没按流程走。

## 第 0 关 · 构造效度（排序之前先问：score 是不是一把尺子）

**IC 只能检验「排序」，不能检验「这个分数有没有资格被排序」。** 复合打分器里凡出现
门控后加权、`min(score, X)` 封顶、`max(score, X)` 托底、分类判定后二次赋值，分数就只对
同一条分支内的样本可比。跨组算一个全池 rank-IC，量到的是这些人为构造的混合物，
不是策略的排序能力——数字没错，指称错了。

开工第一步跑探针，30 秒替代三小时白跑：

```bash
python scripts/probe_score_construct.py --db audit.db --group cat --threshold 85 --fwd fwd5
```

三件事必须看：

1. **单一取值聚集**：某组 80% 以上样本落在同一个分数上 = 封顶/托底的铁证。该组在全池
   rank-IC 里必然垫底，但这与「该组未来更差」无关，纯粹是钉死的数。别把它写成避雷信号。
2. **阈值构成**：`score >= 门槛` 的样本按组构成。若大头来自「观察 / 未满条件」类而非
   「可执行」类，则按分数取 top-N 买到的东西和产品说明不是一回事——**分类标签 ≠ 排序标签**，
   这条单独写进报告，且组合模拟必须按实际入选集合重算。
3. **每日候选只数分布**：中位 90 只而某天 1554 只，说明门槛在极端日失效，那天的 top-N
   等于随机抽样，等权组合只是在噪声里抽样。

判决怎么改：受污染的分数**只能给 L0 描述**；干净用法是**组内排序**（同一组内比），
组间只比成败率/均值差（事件式口径，见 `references/score-construct.md`）；
策略层另算一遍，不能拿全池数字代替。

## 七关一览

| # | 关卡 | 命令 | 判死线 |
|---|---|---|---|
| 1 | IC / t | `vkit.py ic --trials N` | \|t_HAC\| 低于 Bonferroni 门槛（1次1.96 / 4次2.50 / 12次2.87） |
| 2 | 衰减 | `vkit.py ic`（多持有期） | 负值随持有期单调放大 = 稳定反向 |
| 3 | 分段 | `vkit.py ic`（rolling） | 8 段同号且无结构 = 一致无效 |
| 4 | 分年 | `vkit.py yearly` | 早期正、最近一年负 = 近期证据不支持，**不是**"永久失效"；最后一年只有规则提前冻结才算样本外 |
| 5 | 经济量级 | `ic --cost 0.20` | 按价差符号定方向后，多头腿超额 − 成本 <= 0（A股 0.15–0.25%/腿）= L3 |
| 6 | 集中度 | `vkit.py conc --rows` | 剔 5 天转负 **且** 那几天事前不可识别 = 不可重复 |
| 7 | 组合模拟 | `vkit.py sim` | 任一离场规则劣于"不动"时，按收益/尾部/换手三者一起判；t 要过"重叠校正"列，且**不能当上线证据** |

横向：`vkit.py timing`（择时真假，以 t(HAC) 为准）+ **类别标签回查代码分支**。

## 使用

```bash
cd factor-verdict          # 解压后的目录
python scripts/vkit.py selftest            # 必须先跑，十八项全过才可用
python scripts/vkit.py ic --bars data/bars --factor data/factor.csv --trials 4
python scripts/vkit.py ic --bars data/bars --factor data/factor.csv --trials 4 --cost 0.20
python scripts/vkit.py conc --rows trades.csv
python scripts/vkit.py sim --bars data/bars --signals signals.csv --hold 20   # 默认 --entry close，与 ic 同口径
python scripts/vkit.py timing --signals signals.csv --index index.csv --hold 20
python scripts/vkit.py yearly --bars data/bars --factor data/factor.csv --horizon 5 --trials 4
```

纯标准库。数据格式见 README.md；从审计库导出这些 CSV 用 `examples/export_from_db.py`。

- **仓是源**：`~/factor-verdict` 为主副本，技能目录里的是拷件。改完脚本必须
  `cp -r factor-verdict/{scripts,references,*.md} <技能目录>/`；两边不一致时以仓为准，先同步再引用结论。
  两侧可能各自改过不同文件，**先 `diff -r` 看清楚再合并**，不要假设仓一定是最新的；
  收到外来 zip 时的标准动作见 `references/reconciling-copies.md`（分叉≠新旧，按函数比、用对抗输入实测）。
- **产物去处**：真实数据跑数存 `~/factor-verdict-runs/YYYY-MM-DD-<范围>/`
  （`data/` + `reports/` + `RUN.md`），总索引 `factor-verdict-runs\INDEX.md`；
  临时目录会被清，导出完就搬进去。数据源是点开头的隐藏目录，给用户一律用可见目录联接。
- **大样本走 `db_lab`，别走 CSV**：`ic --factor` 会连 factor.csv 带 bars 一起读进内存，
 百万行级别直接吃光。审计库已把 (date, sym, score, fwd) 落表，用
  `db_lab.series(db, horizons, cat=, lo_score=, hi_score=, date_from=, date_to=)` 流式直读——
  410 万行 × 4 持有期约 185 秒，峰值内存只占单日截面；`db_lab.walkforward()` 做真外推。
  一次扫描里把所有切片（按年、按组、按 regime）的统计一起累加，别为每个切片重扫一遍。
  走不通再退回 `export_from_db.py --max-codes N` 分子集，并在报告里写明全池还是子集。

## 统计约定（v1.3 强制）

- **重叠样本必须校正，且 Bartlett 不够**：前向收益重叠 → IC 与配对差都用同一套
  ——**平坦权与 Bartlett 取较大方差 + 自由度 n/(2·lag+1) 的 t 临界值**（`factor_lab.hac_t_overlap`）；
  择时用 HAC-OLS。只用一个 Bartlett HAC 仍会低估（实测同一份 20 日 IC：−2.20 → **−1.83**，
  跨过 1.96 线）。**名义 t 一般虚高 3–7 倍**；配对差从 −21.98 修到 −3.36，再修重叠后更靠近 0。
- **估不出来就写不可估**：有效自由度 < 3（信号日少于约 6H）时不给 t；平坦权 HAC 可能算出负方差
  （不是半正定）→ 方差取 max(平坦, Bartlett)，退化单列标记。不可估 ≠ 不显著。
  同一原则适用于交付：空档位返回 NA（不是 0）、IC 零方差标退化、因子全同分/未来收益全相同的
  截面直接剔除并报数（不是记成 IC=0 计入自由度）。
- **并列因子同分同档**，结果不得随输入顺序变化。
- **判定与数字必须来自同一个变量**：结论行不许用朴素 t、表格用校正 t。两处口径不一致时，
  同一份报告会同时说"显著"和"不显著"，而读者只记住结论。
- **成本按数据方向扣**：先由价差符号决定做多哪一档，再扣成本；A 股零售默认按"只用多头腿"判可实施性。
- **不得因入场价与止损位的关系删除样本**；跳空开盘已在止损下方时，照常计入并在开盘价离场。
- **非法数值必须报错**，不许静默归零。
- **无重算命令 = 无数字**：报告里每个数字都要挂一条能重现它的命令。

## 三条最容易骗自己的地方

1. **样本量翻转符号**：438 只上 +1.22%、3018 只上 −1.76%，同一个类。少于几百个横截面日的只能当假设。
2. **多重检验**：试 4 个变体挑最好看的，t=2.0 不算过线。回测前写下 Gate，改一次算多试一次。
3. **整体显著掩盖结构**：整体 IC 显著，拆开可能"中段负、最高段正"；再分年，正号可能只在前四年。

## 快速通道（审一份现成报告，30 分钟）

不跑全流程，只查八项：样本量、口径（超额还是绝对）、成本、分段、分年、集中度、标签与代码是否一致、
数字有无重算命令。任一项缺失，结论降为 L0/L1。

## 边界（完整度自评）

只做单因子截面检验。不处理多因子正交化、行业/市值中性化、组合换手与容量。
单因子没过 t 检验之前，中性化只是给噪声做美容。

被问到「完整度」时直接给这张表，不要含糊：

| 能力 | 分 | 现状 |
|---|---|---|
| 构造效度（第 0 关） | 8/10 | 探针能定性封顶/托底/阈值构成；跨类归一后的实际信息量仍靠手工算 |
| 因子/信号证伪 | 7/10 | 真实数据上全池与分组会反号，且工具零输出判级；单看全池 t 会下错结论 |
| 分档 / 成本 | 6/10 | 方向按数据定；分档塌缩不披露（某组 1409 个 IC 日只剩 82 天出档），成本仍是常数且三处口径不一 |
| 分年 / 分段 | 8/10 | `vkit.py db --walkforward` 已接通 CLI，`trials` 自动计入 Bonferroni 门槛 |
| 数据口径 | 4/10 | 两个库行数相同 score 不同、无名指纹；fwd 精确为 0 的占 3.18% 未被标出 |
| 大样本工程 | 8/10 | `db_lab` 直读 410 万行 185 秒，已接进 `vkit.py db` CLI 并带参数化与入口校验 |
| 基准 / 超额 | 3/10 | 只有「相对全池均值」；`bench_*.json` 没有命令能读 |
| 组合回测 | 1/10 | `sim` 是逐笔等权而非逐日组合；无成本、无仓位、无净值、无换手 |
| 成交假设 | 6/10 | 已拦截 T+1 停牌与一字涨跌停买入，一字跌停止损顺延至开板日；盘中排队与冲击滑点未做 |

一句话：**证伪器约 6.5/10，回测引擎约 2/10。** 它回答「这条结论能不能信」，不回答
「这个策略能赚多少钱」。被问「能不能直接当回测用」——不能，四个硬缺口按影响排是：
**成交假设 → 组合层（仓位/止损/容量/净值）→ 基准与中性化（剥 β、行业市值）→ 工程（CLI 化、索引）**。
注意：缺口排序里「分组与构造效度」曾经漏过，它排在成交假设之前——所以现在它是第 0 关，不是待办。

## 交付物必须包含

1. 数据口径（样本、区间、观测数、成本与成交假设）
2. 七关数字表（不是结论，是数字）
3. 判级理由：**哪几条解释被数据排除了**
4. 数字可信度速查表：哪些能引用，哪些不能
5. 未覆盖的边界（前视、幸存者、样本外、容量）
6. 若任一项缺失 → 首页标 **"仅方法演练，不可引用"**
