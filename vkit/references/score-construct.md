# 构造效度 · 复合打分器能不能当尺子排序

只做一件事：判断「把 score 从高到低排一遍」这个动作在这份数据上是否合法。
不合法时，全池 IC 不是错的数字，是**指称错了**——它量的是构造，不是能力。

## 一、三类污染，按代码形状认

读打分函数，找这四种写法。找到几个，就有几层不可比。

| 类型 | 代码形状 | 后果 |
|---|---|---|
| **门控型** | `if not (a and b): 仍继续算分` | 没过门槛的样本带着分数留在池里，与过了门槛的同池排序 |
| **托底型** | `if 战术条件: score = max(score, 88)` | 战术动作拿到高分，压过质量分高的正经标的；top-N 被它挤占 |
| **封顶型** | `if 危险条件: score = min(score, 35)` | 该组在 rank-IC 里必然垫底，与「该组未来更差」无关 |
| **分档赋值** | 先算 cat，再按 cat 给不同基分 | 组间分数不同源，跨组比较无意义 |

封顶/托底最阴的地方：它产生的不是噪声而是**秩序**。排序稳定、IC 显著、分段一致、
扣成本后仍显著——七关全过，因为它量的是一条写死的规则，不是市场。

## 二、探针：三张表定性

```bash
python scripts/probe_score_construct.py --db audit.db --group cat --threshold 85 --top 20 --fwd fwd5
```

**表 1 单一取值聚集度。** 每组里出现次数最多的那个分数占全组比重。
> 80% = 封顶或托底。此时该组的 rank-IC 一律不得引用。

**表 2 阈值构成。** `score >= 门槛` 的样本由哪些组构成，各占多少。
读法：门槛之上如果「观察 / 未满条件」类占大头，而「可执行」类只占个位数百分比，
说明策略文字说的和代码做的不是一件事。这不是统计问题，是**文档与实现不一致**，
按缺陷报，不按因子报。

**表 3 每日候选只数。** 中位 / 均值 / 最大 / 最小。
读法：最大值远高于中位（如 1554 vs 90）= 门槛在极端行情日失效。凡是按 top-N 取样的
组合模拟，这些日子等于随机抽样，要么剔除并报数，要么在结论里标出占比。

## 三、污染之后的三种合法口径

1. **组内排序**（首选）：同一组内做 rank-IC + 分档。组内分数同源，这是唯一干净的用法。
2. **组间事件式**：不排跨组的名次，只比「这批样本的未来收益 − 同日全池均值」的配对差，
   报 n、配对数、t_HAC。适用于被钉死分数的组（封顶组、托底组）。
3. **策略层重算**：按真实入选规则（top-N + 门槛 + 仓位约束）重建持仓集合，算净值。
   全池 IC 无论如何都不能代替这一步。

## 四、样本太小怎么办

每日截面只有个位数样本的组（稀有形态：狙击就绪、深 V 反转、连板妖股），日度 IC 基本无定义，
`min_n=20` 会把它们整组剔掉。**剔掉不等于没有**，正确写法：

- 走事件式：全样本聚成一批，与同日全池均值比，给 n 与日均只数。
- 判级直接标 **L0**：几个月级别的样本量撑不起"有效/无效"，只能写"观察到的方向"。
- 报告里写清每日只数——每天 2 只的信号，即使 t 显著也没有容量，与 L3 同一个下场。

## 五、组合模拟前必须截断

前向收益里的极端值（新股首日、复权拼接、数据错位）会主导净值。模拟前按
`|fwd| > 60%` 截断或剔除，**并报截断条数**：

```sql
SELECT SUM(fwd5 > 0.6), SUM(fwd5 < -0.6), SUM(fwd5 IS NULL) FROM rows;
```

条数以千计说明数据本身有结构问题，要在数据口径里写明，不能只写「已清洗」。

## 六、并行审计的分工纪律

一个策略要同时补五六个缺口时，拆成并行子任务比串行快一个数量级，但有三条必须写进任务书：

1. **共享一份 `CONTEXT.md`**（库路径、字段、口径、已知坑、工具 API）+ 一份 `TASKS.md`（验收标准）。
   每个子任务自读，不要在任务描述里各写一套参数——那会长出六个口径。
2. **禁止子任务改主仓**。新代码一律写进本次跑数目录的 `scripts/<task>_*.py`。
   并行改同一个仓必然互相踩，且事后无法分辨哪行是哪个任务改的。
3. **子任务只报数字，不判级。** 判级由汇总方独占，理由是跨任务的矛盾（同一个 IC 两处不同）
   只有在汇总时才能发现；让子任务各自下结论，会得到六份互相矛盾的判决书。

子任务产出固定三件：`reports/<task>.md`、`data/<task>.json`、`PROGRESS.md` 追加一行。
