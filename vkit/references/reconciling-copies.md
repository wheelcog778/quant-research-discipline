# 合并两个分叉副本（外来 zip / 另一台机的版本）

适用：用户丢来一个 zip、一个旧包、或"你看这个版本"，要判断该不该覆盖本仓、往哪边合。
**这不是新旧关系题，多数是平行分叉题。** 直接 `cp -r` 覆盖任一侧都会丢东西。

## 步骤

1. **解压到 scratch，先看包内每个文件的 mtime**，与仓里同路径的 mtime 并列。
   包内 mtime 比仓新 ≠ 整包新，只说明那一个文件新。
2. **分层判新旧**，不要拿顶层的版本号或 README 定调：
   - `scripts/`（`vkit.py`、`factor_lab.py`）：判定逻辑，风险全在这里
   - 顶层 `SKILL.md` / `README.md` / `references/*`：口径与文档，常被后改
   - 新目录（`pool_lab`、`db_lab`、`probe_*`、`references/verification/`）：只在一边，按功能并入
   典型陷阱：仓的文档已到 v1.5，而 `scripts/` 的 mtime 停在上一轮审查之前——文档看起来最新，脚本是旧的。
3. **数自检项，别看"全部通过"**：`grep -c '=== 自检' scripts/vkit.py`，再跑 `selftest` 记 `x/N`。
   两边都通过只证明各自内部自洽；N 不同说明覆盖的失败模式不同，弱的一侧可能整整缺一类检查。
4. **按函数比脚本，不用整文件 diff 的 hunk 数定方向**：几百行"只在 A 侧"的行常常是重构。
   用 AST 提取每个顶层 def/class 的源码，归一化空白后比，得到三列：只在包内 / 只在仓内 / 两边不同。
   只有"两边不同"和"只在某一侧"的函数才需要读。
5. **回归用对抗性输入实测，不信 changelog 自称修过**：
   构造最小数据（`vkit_selftest/bars` 60 只 × 320 天，配一份随机 `date,code,value` 的 factor.csv 即可），
   分别用两版的 CLI 打非法参数（负持有期、`--hold 0`、`volume<0`、空日期、重复 code），
   看谁静默出表。**静默接受 = 能出假结论**，比缺一行文档严重。
6. **出结论**：指定哪边做基线 + 逐条移植清单 + 明确禁止覆盖的条目。
   统计量类修复按"谁有实测校准"取，文档与输入校验类按"谁补了"并入。

## 合并取向（本仓的既有判断）

- 保留本地有**假阳性实测**的统计量：`overlap_t`（按日等权 → 平坦/Bartlett 取较大方差 → 有效自由度临界值，
  实测 69.2% → 5.0%）。对方若只有 pooled Bartlett（无有限样本自由度修正），自检只验证"t 显著收缩"，
  没校准过假阳性率——不能换。
- 保留本地口径统一：`sim --entry close` 与 `ic` 逐位一致；外来版可能仍写"T+1 开盘入场"，
  自称修了口径其实只修了持有期边界。
- 移植外来版的**输入校验**（正整数/非负校验、重复持有期拒绝、`volume<0`、空日期）与**退化处理**
  （`spread_summary` 返回不可估 + HAC 列，而不是 `pstdev or 1e-9`）。
- 移植外来版的**文档修正**：`references/data-sources.md` 里"深于 −11.5% 只能是除权、整体缩放"是
  已被推翻的写法，正确版是"可能除权，须公告/股本/第二数据源交叉验证，先分类再决定是否调整"。
- 只在一边的新关卡/新工具（构造效度探针、池子分解）整块并入，不重写。

## 给用户的报告形状

先给一条能复现的证据（命令 + 真实输出 + 一行判语），再说结构。
例：`ic --horizons -5` 在仓内正常出"−5日"表、IC +0.0171、t +2.23、标 ✅显著，外来版直接拒绝。
然后是三段：外来包是什么 → 仓里现存的漏洞 → 两边各自独占的修复 → 一句"要不要合"。
